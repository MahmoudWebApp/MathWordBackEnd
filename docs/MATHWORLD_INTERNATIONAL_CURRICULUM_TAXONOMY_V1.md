# MathWorld — International-aligned Curriculum Taxonomy v1

> **Review proposal; not seeded or published.** 10 navigation categories per stage are MathWorld-specific, aligned to—not literally prescribed by—Cambridge, Common Core, PISA, CUPM and MSC2020.

## Global reference hierarchy
- Cambridge Primary & Lower Secondary Mathematics + Common Core K–12: grade progression and skill coverage.
- OECD PISA mathematics: cross-topic reasoning/process tags (formulate, employ, interpret/evaluate), not navigation categories.
- MAA CUPM: undergraduate course/program curriculum structure. MSC2020: university mathematical subject tags, not lesson order.
- Regional school curricula can map into these immutable skill keys without renaming the student-facing subjects.

### Quality flags
- Exact duplicate IDs: 3/4; do not delete until progress references are checked.
- Repeated templates differ in numerals: mathematical review must verify diverse cognitive processes, not multiply essentially identical drills.
- User attempts/progress refer to immutable `ProblemId`; category changes may alter Free entitlement and must undergo an access-policy migration.

## Question type and acceptance model
Every question owns exactly one primary skill key and category key; related prerequisite skills can be secondary metadata but never used to mix categories.
- 100 initial questions per category = 10 stable groups of 10, curated across conceptual understanding, fluency, application, reasoning and multi-step problem solving.
- Every item: bilingual equivalent question, four DISTINCT plausible choices, exactly one mathematically verified correct choice, worked bilingual solution, correct typesetting on web/Flutter, difficulty 1–5, one PISA reasoning tag, stable content key and family/template key.
- Validation: duplicate exact/semantic/template check, CAS/symbolic or numeric verification where applicable, answer/solution consistency, maths reviewer acceptance, bilingual reviewer acceptance, preview on both platforms.
- Flow: draft → automated validation → editorial review → approved batch → one atomic idempotent publication → audit against expected category counts. Auto-generated drafts never auto-publish.

## Expansion contract
1. New request to 'add questions' resolves existing stage/category/skill keys first; it must never create a near-duplicate category.
2. A new category is justified only when the concept is distinct and cannot fit a coherent existing primary skill domain; category caps are for the first launch, not a lifetime restriction.
3. Add curated questions to fixed topic groups in increments; lock group membership and preserve solved history.
4. No updates to legacy IDs, progress, attempts, subscriptions or Free category picks in an editorial batch.
5. Future universities specialisms (complex analysis, topology, PDE, etc.) expand the taxonomy intentionally rather than shoehorning unrelated questions into ten categories.
6. When user selects locale/grade, map objectives to local curriculum while stable `stage/category/skill` references stay unchanged.
7. Never deploy schema/content changes before review of the crosswalk, Free access impact and a reversible database transaction.
