# Learning tracks: additive rollout
- Four existing stages and their IDs remain unchanged. Twelve school grades (6/3/3), plus five initial university courses, are seeded unpublished; additional university courses can be added by editorial administration.
- Track/category, track/skill and track/problem are many-to-many join tables. A problem shared across tracks is still one problem ID and one learner progress history. CurrentTrackId is nullable, no grade inferred for any existing learner.
- For an active selected track, Free access resolves its first two populated categories by editorial order then ID. Legacy unselected stage access retains the stage-wide pair. Publication must verify reviewed mappings, valid category/skill stage consistency, at least one real accessible problem and Free coverage; no public empty track.
- Legacy reads remain stage-based until web and Flutter track-aware contracts and content mappings are ready. Do not activate in production before both clients support track selection and scope. No data migration assigns existing problems without review.

Public stage track catalogs now use a shared validated link query and one grouped coverage query for all tracks, plus a single stage Free-category snapshot. No per-track query loop, no user-specific cache. Invalid selected tracks fail closed in CanPracticeAsync rather than falling through to unrestricted stage practice. Existing overlapping-track integration checks both public counts. Web adds localized server-rendered public track URLs, published-only sitemap and canonical/hreflang metadata; student-only verification pages are noindex. No deployment.

## Owner decision 2026-11-26
University will use two levels as the same LearningTrack abstraction as school grades. Do not retire the seven existing course identities or change historical practice scopes until the reviewed content mapping and history compatibility are ready. Launch target: 14 tracks × 5 populated categories × 20 distinct problems = 1,400 assignments. Current change only unifies the Free category policy and simplifies the validated membership query; it does not migrate university data.
