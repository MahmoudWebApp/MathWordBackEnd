# G1-07/08 — independent session foundation (feature disabled)

This additive slice introduces LearningSessions and LearningSessionAttempts through EF migration 34. Existing UserProgress, ProblemAttempts, favorites, points, Free category selections, legacy reset and legacy daily challenge are untouched. The new route is /api/users/learning-sessions, gated by LearningSessions__Enabled (default false). No production migration or activation.

- POST start: server resolves current stage, visible selected track, Free/Premium category eligibility; 5–10 practice questions, exactly five for Premium daily. Insufficient content returns conflict, not fabricated questions. One daily session per learner per UTC date across devices and scopes; returning to original scope is required after switching. One unfinished practice session per stage/track/category scope. Start request replay and DB uniqueness prevent duplicate active sessions. Completed daily remains available by ID/current for card suppression.
- GET current or GET {id}: explicit question projection, never correct option or solution before session success; no cross-owner reads. A question's immutable text/option fingerprint detects changed source rather than grading silently against a different version.
- POST {id}/answer: validates owner, current scope, current category entitlement, daily date, question position, option ownership and content fingerprint. Shared question lock + existing learner advisory lock serialize updates. Request UUID makes a submitted attempt idempotent; wrong answers do not advance; correct answers advance once. Each attempt keeps selected option text, number and submitted time. A replay does not award or advance again. The server returns solution only for a correct session attempt.
- No global points, badges, mastery, shared progress, or hint integration yet. Session-only data is deliberately not counted in legacy aggregates. Do not activate until the next slice integrates permanent achievements and independent cycles, scoped reset, hint usage, legacy route transition, Web + Flutter, server-owned badge issuance, and first-correct reporting. Explicit API tests use disposable PostgreSQL, never production.
- Historical scope IDs and question fingerprints are stored without foreign keys to mutable catalog objects; account deletion follows existing learner-data cascade. An inaccessible/changed item fails closed, not silently replaced. Design an explicit audited abandonment/replacement flow before production activation.
- Date boundary: UTC, same as existing challenge policy. No device-generated completion or daily reward.

## Hint evidence and achievements
Migration 35 adds current session hint count and immutable per-attempt UsedHint. Hint level 0 restores revealed text; 1/2 reveal sequentially for Premium only; missing editorial hints are never synthesized. Each reveal writes one activity event under learner lock; answer snapshots assistance before advancing and clearing current hint state. Session achievements derive only from completed session records and correct attempt evidence: first practice, first daily, seven distinct completed UTC days, perseverance after retry. Keys are unique and earned dates are stable. Read access is independent of current stage and subscription expiry, because the achievement was earned historically. Counts distinguish unique problems, correct session answers and unassisted first-attempt success; session counts must not simply be added to legacy counts. The new solution response supports existing localized structure after correctness. Remaining: integrate global permanent points/progress, reset scope, old routes, both clients, audited recovery from invalid content and complete release acceptance; no activation or production migration.

## Permanent ledger and scoped session restart
Migration 36 creates a lifetime learner/problem achievement keyed independently of current practice progress. Backfill uses historical correct ordinary attempts (maximum recorded award, not sum) or legacy solved rows without correct audit evidence (current catalog points as a documented fallback). Both ordinary and session answer paths award through the same ledger under the existing learner lock. A second solve in another session or ordinary practice awards zero. The achievement API exposes permanent points and solved count separately from session counts and the existing active-cycle journey. Session abandonment explicitly targets one current-scope unfinished practice session, preserves attempts and achievement evidence, frees its active slot, and never abandons daily challenges. No student progress, favorites or history is deleted. Remaining: active-cycle scope model for ordinary practice reset, unified leaderboard/report read integration, client interfaces, and release acceptance. Do not enable the feature before those are integrated.

## Scoped session restart and lifetime journey fields
Fix abandonment timestamps to PostgreSQL microsecond precision so identical retries produce identical responses. New GET/POST restart-scope preview/confirm accepts exact unfinished practice session IDs in the current stage/track, optionally a category; stale IDs or scope fail closed, and replay never abandons newly created sessions. Category restart does not abandon unrelated stage-wide or other-category sessions. Stage/track restart abandons all unfinished sessions in that exact scope; daily, completed sessions, history, favorites and ledger are untouched. This is scoped session restart, not yet a replacement of ordinary UserProgress reset. Journey adds separate PermanentSolvedProblems/PermanentPoints at category and scope totals without changing existing active-cycle fields. Ordinary milestone notices now use new ledger entries and lifetime counts instead of resetting active solve count. Remaining: ordinary per-track cycle projection, permanent leaderboard/report integration, client parity, approved content and production acceptance. All previous plan requirements remain open until verified.

## Permanent student ranking and capability
Student leaderboard switches to the lifetime ledger only with LearningSessions enabled, retaining SQL pagination, actual active student names, stage privacy, and rolling windows by original earn date. The first-try tie breaker uses immutable unassisted evidence on the original award timestamp; old rows without verified evidence receive no first-try credit. Journey exposes LearningSessionsEnabled for clients, avoiding guessing rollout readiness. Admin ranking/analytics and full ordinary cycle projection remain separate outstanding work.

CI fixture correction: the disposable track fixture deliberately solves then deletes its test problem; assert its permanent credit exists and explicitly clean only that fixture's ledger row before unrelated unranked-learner assertions. Production history is never removed. Added reset/ranking regression; session selection now prefers problems not yet permanently earned, and session answers use existing answer rate limiting.
