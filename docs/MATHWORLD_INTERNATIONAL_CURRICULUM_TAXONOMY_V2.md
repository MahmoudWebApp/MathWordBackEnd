# MathWorld — Adaptive international-aligned mathematics taxonomy (v2)

> **Status: editorial proposal, no production category/problem migrations.** Supersedes the earlier 10×100 fixed-size proposal. International standards inform domain coverage; they do not prescribe MathWorld category counts or licensing.

## Correct roles for each external reference
- Cambridge International / Common Core: coherent school learning objectives and grade progressions, not a ready-made MathWorld 10-topic list.
- OECD PISA mathematical literacy: problem-solving and reasoning processes (formulate, employ, interpret/evaluate), not a category list.
- MSC2020: vocabulary and indexing of advanced mathematical disciplines, not a university lesson sequence. Academic course prerequisites need human curriculum review.
- MathWorld is independent and does not claim endorsement or certification from the referenced organizations.

## Category counts are a RESULT, never a requirement
Provisional expert-editable catalogue: 11 Primary, 12 Lower Secondary, 14 Upper Secondary, 15 University Foundations. These are subject-coherence proposals, not target counts or published counts.
Create a category when its learning goals form a distinct coherent mathematics domain. Split broad existing categories only where its problem types are materially separate and the Free access/progress implications are reviewed. New university subjects may be appended as the content is ready.

## Practice-volume planning (no numerical quota)
1. Define a measurable objective and prerequisites for each skill. Draft only as many distinct mathematical questions as needed to provide multiple independent ways to demonstrate that objective.
2. Select mixed evidence: conceptual explanation, numerical fluency, applied/word problem, reasoning/justification, transfer in a novel context. Not every skill needs every format equally.
3. For each candidate item, record a stable content key, subject key, primary skill key, template family, canonical mathematical expression, difficulty, intended reasoning process and expected misconceptions.
4. Automatically detect exact, near-text, numeric-template and mathematically equivalent duplicates; duplicates are flagged for editor adjudication, not published to meet a count.
5. Require mathematically verified solution and one correct option with three plausible, distinct distractors; review bilingual equivalence and render LaTeX in both web and Flutter.
6. Publish small reviewed sets for specific uncovered objectives. Use student results to identify where new variants or explanation are needed; stop adding repetitive drills when evidence is sufficient.
7. Separately measure existing solved/attempted/mastered problem statuses. A genuine per-skill mastery score requires first tagging existing questions with reviewed skill keys and validating the evidence model. Never display invented mastery.

## Preservation and learner-facing UX
- Never publish empty placeholder subjects just to reach a number; public/free/premium lists remain sourced from published database data.
- Existing solved attempts, scores, progress and paid access must be preserved; Free pair category configuration requires explicit review before reassignment.
- Public site, private web dashboard and Flutter display short bilingual methodology note referencing Cambridge, Common Core, OECD PISA and MSC2020 accurately without accreditation claims.
- Dashboard shows only real completed/attempted/mastered problem counts from the current learner journey API, not an unvalidated skill-performance percentage.
- Stable taxonomy keys allow future skill-tagged imports without making a duplicate near-synonym category.

## Versioning and next batch contract
Each request to add content must identify existing stable categories + unmet learning objectives; when missing, add a distinct category to the proposed catalogue, review, and only publish alongside real questions. Published batches require deduplication across all prior content, human math/editorial approval and a post-insert audit. A category is never complete just because it has exactly N questions.
